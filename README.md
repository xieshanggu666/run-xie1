# 潮汐邮局 Tidal Post Office

一款使用 **Phaser 3 + TypeScript + Vite** 制作的浏览器航海叙事经营游戏。玩家驾驶邮船“退潮针号”，在 6 天一轮的群岛邮路中规划潮汐、燃料、载重、信件密级与岛民关系。

> 你不可能一次送完所有信。错过、抛弃、私拆、补封或守住秘密，都会改变七座岛对你的态度，并影响下一周目。

## 运行

要求 Node.js 18+。

```bash
npm install
npm run dev
```

然后打开 Vite 输出的地址，默认：

```text
http://localhost:5173
```

生产构建：

```bash
npm run build
npm run preview
```

构建产物在 `dist/`，可部署到任意静态服务器。项目资源全部由 Phaser Graphics 程序化绘制，不依赖外部图片或音频文件。

## 基础存档

- 存档位置：浏览器 `localStorage`
- Key：`tidal-post-office-save-v1`
- 槽位内容：带完整性封签（seal）的存档信封。手工修改槽位里的任何数值都会使封签失效，游戏将拒绝读取该存档
- 自动保存时机：接信、交付、等待、买卖、改造和事件结算等港口操作后
- 手动保存：右上角“保存”按钮
- 航行中刻意不落盘；如果航行途中关闭页面，会回到上一次离港前的港口状态
- 标题界面可删除本地存档
- 完成一轮后可保留结局摘要和逐条旧航行日志，进入下一周目；也可以在浏览器控制台执行：

```js
localStorage.removeItem('tidal-post-office-save-v1')
```

## 可携带备份（导出 / 恢复）

多周目结局摘要、秘密标记与最多十轮、每轮最多 100 条的旧日志，全部保存在上面这一个 localStorage 槽位里。清理浏览器数据、换浏览器/设备、误点“删除本地存档”都会永久丢失，因此提供文件级备份：

- **导出**：标题界面（有存档时）或游戏内右侧“记忆”页顶部，点“导出备份”，浏览器会下载单个 JSON 文件，文件名形如 `tidal-post-office-backup-20260910-1618-cycle3.json`，包含当前进度与全部已归档周目。
- **恢复**：标题界面或“记忆”页点“从备份文件恢复 / 恢复备份”，选择备份 JSON。确认弹窗会显示备份时间、周目、银币与已归档结局轮数；确认后**整体覆盖**当前浏览器存档并打开“记忆”页。
- 备份是纯 JSON、不依赖任何服务器，可自行拷贝到 U 盘、网盘或其他设备长期保存。
- **手工修改过的备份一律拒绝加载**。每个备份都是一个固定 6 字段的信封（`app / kind / format / at / state / seal`），封签对**整个信封**计算——不仅存档数据，连确认弹窗里显示的备份时间（`at`）、格式号（`format`）、类型标记（`kind`）也一并绑定。只改一个字节（把信件重量改成负数、把备份时间改成其他日期、伪造格式号、增删任何字段）封签就不匹配，弹窗会明确提示文件被手工修改，在校验通过前绝不写入存档槽位——不可能出现“好存档被坏备份覆盖”。
- 信封元数据同样严格校验：键集合必须恰好是约定的 6 个字段；时间戳必须是规范 ISO 格式且是真实日期（`2099-13-45T99:99` 这类伪造日期会被挡下）；格式号必须是正整数且不高于当前版本；备份文件与槽位存档的 `kind` 不可互换。所有信息在验签通过前都不可信、不会展示给玩家。
- 封签之外还对 state 做逐字段的结构与数值范围校验：类型、整数性、取值区间（如重量必须为 1～20 的正整数、关系 0～100、升级 0～3、燃料不超过煤油柜容量、航行进度不超过总距离、id 不重复、周目日期格式等）以及跨字段一致性（送达不早于接载、船壳不高于上限等），错误会定位到具体字段。标记键采用"游戏事件白名单 + 每日刷信动态标记（`mailDayN`）"的形式，与游戏实际写入的数据严格对齐；校验覆盖全部海上/港口事件的所有分支，并通过完整的多局流程模拟回归，确保正常游戏产生的任何存档都不会被误判为损坏。
- 恢复入口**只接受游戏“导出备份”生成的带封签文件**；手拼的裸 JSON（包括直接从 localStorage 复制的内容）会被拒绝，以防绕过规则。旧版本未加封签的本地槽位会在首次读取时自动迁移、下次保存即改为全信封封签格式。
- 写入后还会立即回读校验：万一写入异常，会自动恢复原槽位；若原槽位本身已损坏，则清除坏数据并返回标题界面。
- 说明：封签是防呆/防随手作弊的完整性校验，并非加密签名（盐值在前端代码中）；刻意逆向仍可绕过，但常规的文件编辑、元数据伪造都会被挡住。
- 标题页与游戏内的文件读取/校验失败都通过居中弹窗提示（标题页没有普通消息条）；槽位中的存档损坏时，“读取存档”也会明确提示而不是静默失败。

## 约 20 分钟的推荐初始流程

游戏内每轮 6 天。第一次游玩建议按下面节奏熟悉系统：

1. **潮汐港邮局**
   - 初始 30 银币、16 燃料、8 单位载重、10 船壳、2 个火漆补封盒。
   - 推荐接：盐税通知、潮湿药方、红蟹锣谱、蓝情书、关税公文。总载重 7。
   - 第 1 封遗嘱先不要带，也不要为了好奇拆它。
2. **等到 08:00 左右**
   - 开局是低潮，盐泽礁浅滩未开放。
   - 可直接扬帆在海上等潮，也可在港口点“等 1 小时 / 等到下次涨潮”。
   - 首次出航会触发老局长的潮汐课，认真听讲可获得潮汐历。
3. **潮汐港 → 盐泽礁**
   - 送达盐税通知和药方。
   - 视载重接“蟹苗换盐契”。
4. **盐泽礁 → 蟹锣岛**
   - 送达鼓谱；浅滩、风暴、救鼓手少年等事件会改变船壳、关系和后续奖励。
   - 蟹锣岛可修船、改装引擎或加固船壳。
5. **蟹锣岛 → 灯枝岛**
   - 送达蓝情书且未拆封，会得到额外信任。
   - 灯枝岛出售精密时计；雾航事件中时计/望远镜会提供额外选项。
6. **灯枝岛 → 咸望堡**
   - 送达关税公文后，会遇到税关、蓝玻璃短笺和市长支线。
   - 配合检查、贿赂或引用邮政豁免权会导向不同关系。
7. **之后的自由路线**
   - 去棘木湾可能接到无戳机密包裹，需要望远镜或海图线索才能看见暗礁航线。
   - 鸥栖屿与第二回流、观潮台、遗嘱秘密有关。
   - 六天结束自动结算；旧日志、秘密与称号会进入多周目记忆。

## 核心系统

### 潮汐、航线与时间

- 潮位范围 0～1，每 12 小时一次高潮。
- 浅滩航线潮位 **低于 0.35** 时：
  - 扬帆会被迫等待；
  - 机帆可低速硬推，但耗油且可能刮伤船底。
- 航线有距离、浅滩、暗礁、顺/逆流标记。
- 扬帆不耗燃料但更受潮汐影响；机帆更快、稳定，但消耗煤油。
- 未来 6 小时潮位条需要潮汐历。
- 精确 ETA 需要精密时计；没有时计时显示“约 X 小时”。
- 暗礁航线初始不可见，需要铜望远镜或海图线索。

### 信件

每封信包含：

- 出发岛、目的岛
- 重量、报酬、期限
- 公开 / 普通 / 私密 / 机密密级
- 可读正文与特殊事件标记

规则：

- 船上载重有限，必须取舍。
- 到港后，目的岛为当前岛屿的已接信件会自动尝试交付。
- 超期未送达的信件会退回，并同时损害寄件人与收件人的关系。
- 私拆会留下折痕或火漆痕迹；私密、机密信件后果更重。
- 火漆补封盒可重新封口，但机密信或局长遗嘱仍可能被识别。
- 普通信可以抛弃；机密信和遗嘱受规程限制。
- 送达、延误、拆封、抛弃都会进入日志、结局统计和下轮记忆。

### 岛民关系与分支事件

七座岛各有关系值：

- 80+：信赖，提供折扣和特殊选项
- 62+：友善
- 40～61：生疏
- 22～39：戒备，可能涨价或盘问
- 低于 22：敌对

事件包括潮汐课、风暴、浮标求救、税关检查、蓝玻璃贪腐案、棘木湾走私包裹、红蟹节、观潮台旧时计、莫恩遗嘱等。事件选项会检查：

- 工具：潮汐历、望远镜、时计、防水邮袋
- 银币、燃料、船壳
- 信件是否被拆、是否送达
- 当前岛屿关系
- 之前周目留下的秘密标记

### 船舱改造与工具

- **船舱隔板**：每级 +3 载重，盐泽礁。
- **煤油柜**：每级 +8 燃料容量，咸望堡。
- **蟹油机改装**：每级提升机航速度，蟹锣岛，但耗油增加。
- **加固船壳**：每级 +1 最大船壳并降低风暴风险，蟹锣岛。
- **潮汐历**：显示精确潮位，潮汐港；首课可免费获得。
- **精密时计**：精确预计航线时间，灯枝岛/鸥栖屿事件。
- **铜望远镜**：揭示暗礁航线，降低雾、漂浮物风险，咸望堡。
- **防水邮袋**：风暴不损坏信件，私拆机密更隐蔽，盐泽礁。
- **火漆补封盒**：消耗品，各岛可买。

### 航行日志与多周目记忆

- 日志记录航行、信件、关系、船舶、事件、周目。
- 本轮统计包括送达、延误、私拆、抛弃、风暴、事件数。
- 六天结束产生称号和分数。
- 最近 10 次结局保存在“记忆”页；每次结局会额外归档该轮最新 100 条具体日志。
- 开始下一周目后，在右侧“记忆”页点击对应周目按钮，即可分页查看上一轮的出航、等待、信件交付/超期/私拆、关系变化和分支事件记录。
- 旧版本存档（本次修复前产生）只有结局摘要、没有逐条日志快照；完成新的一轮后即可查看具体旧日志。
- 新周目继承：
  - 少量启动银币（最多 +18）
  - 旧日志摘要、逐条日志快照和秘密标记
  - 莫恩等角色对旧选择的记忆
- 不继承超载、无限燃料或破坏平衡的装备，保证每轮仍需重新规划。

## 操作说明

全程鼠标点击：

- 右侧“港口”：等待潮窗、选择航线、切换扬帆/机帆、出航
- 右侧“信件”：查看、接载、阅读、补封、抛弃、交付
- 右侧“船舶”：购买燃料、修船、升级、购买工具
- 右侧“日志”：查看最近事件与关系变化
- 右侧“记忆”：查看本局统计、选择旧周目并分页阅读归档的具体航行/信件/事件日志
- 右侧“帮助”：游戏内规则手册
- 地图：彩色线显示航线；红点/青点表示浅滩状态；黄点表示船上有目的岛信件；红点感叹号表示当前岛事件

## 项目结构

```text
src/
  main.ts                 # Phaser 启动配置
  types.ts                # 全部游戏数据类型
  data.ts                 # 岛屿、航线、信件、升级配置
  engine.ts               # 状态、潮汐、航线估算、交付、存档与本地备份、结局规则
  events.ts               # 多分支海上事件与港口事件
  scenes/
    GameScene.ts          # 地图、UI、弹窗、航行循环与交互
index.html
vite.config.ts
tsconfig.json
```

## 设计提示

- 第一轮不要追求全送达；优先体验不同选择。
- 想走高信任邮差路线：不要拆私密/机密信，准时送达蓝情书、关税公文和遗嘱。
- 想走灰色航线：提高棘木湾关系，接无戳包裹，再去鸥栖屿调查第二回流。
- 若浅滩挡住航线，先看未来潮位；若燃料紧张，宁愿扬帆等潮。
- 机密公文被拆后即使补封也有风险，最好的“工具”是不打开它。
